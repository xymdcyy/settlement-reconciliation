# 迁移计划

> 本文档描述从 Excel 台账迁移到系统的标准、工具、步骤和验收标准。
> 所有迁移工作必须遵循本文档。

## 1. 迁移策略

### 1.1 总体策略：**试点 → 全量，分批切换**

```
阶段1: 试点（4客户，1-2个月）
  ├─ 潍坊百货、全福元、河北劲草（台账+开票）
  └─ 天猫优品（台账+核对+开票，已有引擎）

阶段2: 全量推广（200客户，6-12个月）
  ├─ 批次1: 有对账单客户（50-80个）
  └─ 批次2: 无对账单客户（120-150个）
```

### 1.2 切换方式：**冻结期 + 全量导入**

**冻结期操作**：
1. 冻结前：财务整理 Excel 台账（清洗脏数据）
2. 冻结期（1-2周）：
   - 业务继续，但**不更新 Excel**
   - 新产生的数据记录在临时表（纸质/临时Excel）
   - 导入工具全量导入历史数据
   - 验证数据完整性
3. 解冻后：
   - 系统上线，补录冻结期数据
   - Excel 封存（只读）

## 2. 标准台账定义

### 2.1 核心集字段（所有客户强制）

| 字段名 | 类型 | 说明 | 枚举值 |
|--------|------|------|--------|
| billing_status | 枚举 | 开票状态 | unbilled(未开)/billed(已开)/split(已拆分)/partial(部分开票) |
| invoice_no | 文本 | 发票号 | - |
| invoice_date | 日期 | 开票日期 | - |
| split_note | 文本 | 拆分说明 | - |
| remark | 文本 | 备注 | - |

### 2.2 扩展字段（客户级配置，需审批）

| 客户 | 扩展字段 | 理由 |
|------|----------|------|
| 潍坊百货 | 红通号、红票勾选台数 | 红冲跟踪 |
| 日照凌云 | 台数 | 手工核对辅助 |
| ... | ... | ... |

**配置格式**（customers.extra_fields_config）：
```json
[
  {"name": "红通号", "type": "string", "required": false, "comment": "红字通知单号"},
  {"name": "红票勾选台数", "type": "number", "required": false, "comment": "红冲台数"}
]
```

### 2.3 状态枚举值定义

**billing_status**：
- `unbilled`：未开票（默认）
- `billed`：已开票（已填发票号）
- `split`：已拆分（父行）
- `partial`：部分开票（暂不使用，预留）

**Excel 值映射**：
| Excel 值 | 标准值 | 说明 |
|----------|--------|------|
| `已开` / `111` / `手工标识已开` / `25年已开` / `26年已开` / `前期已开` | `billed` | 已开票 |
| `未开` / 空 / `未开确定` | `unbilled` | 未开票 |
| `已拆分` | `split` | 已拆分 |
| `重复开具：24932...` | `billed` + remark | 状态+备注拆分 |

## 3. 迁移工具

### 3.1 Excel 解析器

**输入**：客户台账 Excel 文件路径
**输出**： receipts 表批量插入 SQL / CSV

**功能**：
1. 自动识别主 sheet（通常是"全品类"或"全品类-X.XX"）
2. 识别手工区列（新方舟销售单号之前的列）
3. 识别系统区列（新方舟销售单号及之后）
4. 数据清洗：
   - 状态枚举值转换
   - 日期格式统一（`2026-08-21` / `2026/8/21` / Excel序列号）
   - 数值格式统一（去除逗号、空格）
5. 脏数据处理：
   - `重复开具：xxx` → 状态=`billed` + remark=`重复开具：xxx`
   - 无法解析的值 → 保留原值 + 标记 warning
6. 生成导入报告：
   - 总行数
   - 成功导入数
   - 警告数（无法解析但已保留）
   - 错误数（跳过）

**伪代码**：
```python
def parse_ledger_excel(file_path, customer_id):
    # 1. 读取Excel
    xl = pd.ExcelFile(file_path)
    main_sheet = find_main_sheet(xl)  # 通常是"全品类*"
    df = pd.read_excel(file_path, sheet_name=main_sheet)
    
    # 2. 识别列
    receipt_no_col_idx = df.columns.index('新方舟销售单号')
    manual_cols = df.columns[:receipt_no_col_idx]  # 手工区
    system_cols = df.columns[receipt_no_col_idx:]  # 系统区
    
    # 3. 数据清洗
    receipts = []
    for idx, row in df.iterrows():
        receipt = {
            'customer_id': customer_id,
            'receipt_no': row['新方舟销售单号'],
            'model': row['产品型号'],
            'quantity': row['签收数量'],
            # ... 系统字段 ...
            'raw_data': row.to_dict(),  # 完整94列
            
            # 开票状态（从手工区解析）
            'billing_status': parse_billing_status(row.get('是否开票')),
            'invoice_no': row.get('发票号'),
            'invoice_date': parse_date(row.get('开票日期')),
            'split_note': row.get('拆分'),
            'remark': row.get('备注'),
            
            # 扩展字段（根据客户配置）
            'extra_fields': parse_extra_fields(row, customer_config),
        }
        receipts.append(receipt)
    
    return receipts

def parse_billing_status(value):
    """解析开票状态枚举"""
    if pd.isna(value) or value in ['未开', '未开确定']:
        return 'unbilled'
    if value in ['已开', '111', '手工标识已开', '25年已开', '26年已开', '前期已开']:
        return 'billed'
    if value == '已拆分':
        return 'split'
    if '重复开具' in str(value):
        return 'billed'  # remark 单独处理
    return 'unbilled'  # 默认

def parse_date(value):
    """解析日期（支持多种格式）"""
    if pd.isna(value):
        return None
    # 尝试 pandas 自动解析
    try:
        return pd.to_datetime(value).date()
    except:
        # Excel序列号
        if isinstance(value, (int, float)):
            return (datetime(1899, 12, 30) + timedelta(days=value)).date()
    return None
```

### 3.2 数据清洗规则库

**文件**：`migration_rules/{customer_slug}.yaml`

**示例**（潍坊百货）：
```yaml
customer: 潍坊百货
slug: weifangbaihuo

# 手工区列名映射
column_mapping:
  是否还需开票: billing_status_hint  # 辅助列
  是否开票: billing_status
  发票号: invoice_no
  开票日期: invoice_date
  拆分: split_note
  备注: remark
  红通号: extra_fields.红通号
  红票勾选台数: extra_fields.红票勾选台数

# 状态值映射
status_mapping:
  已开: billed
  111: billed
  手工标识已开: billed
  25年已开: billed
  26年已开: billed
  前期已开: billed
  未开: unbilled
  未开确定: unbilled
  已拆分: split

# 特殊处理
special_rules:
  - pattern: "重复开具：(.+)"
    action: "billing_status=billed, remark=重复开具：\\1"
```

### 3.3 导入验证

**验证项**：
1. **行数验证**：导入后 receipts 行数 = Excel 行数
2. **金额验证**：导入后 SUM(amount) = Excel SUM(签收金额)
3. **状态验证**：
   - billed 行数 = Excel 中"已开/111/..."行数
   - unbilled 行数 = Excel 中"未开/空"行数
4. **抽样核对**：随机抽取 10 行，人工比对系统 vs Excel

## 5. 全量推广计划（200客户，6-12个月）

### 5.1 批次划分

**批次1：有对账单客户（50-80个），3-6个月**
- 优先级：按业务量和匹配复杂度排序
- 每月迁移 10-15 个客户
- 需要开发对应引擎（复用现有架构）

**批次2：无对账单客户（120-150个），3-6个月**
- 优先级：按业务量排序
- 每月迁移 20-30 个客户
- 无需开发引擎，只需台账+开票功能

### 5.2 推广步骤（每批次）

1. **准备阶段**（1周）：
   - 收集客户台账 Excel
   - 分析手工区列名差异
   - 编写迁移规则 YAML

2. **培训阶段**（1周）：
   - 培训财务专员使用系统
   - 发放操作手册

3. **迁移阶段**（1-2周）：
   - 财务整理 Excel（清洗脏数据）
   - 冻结期
   - 批量导入
   - 验证

4. **切换阶段**（1周）：
   - 系统上线
   - 补录冻结期数据
   - Excel 封存

5. **稳定阶段**（2-4周）：
   - 监控使用情况
   - 收集反馈
   - 迭代优化

### 5.3 风险控制

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据迁移错误 | 高 | 导入验证 + 人工抽样 + 回滚机制 |
| 财务抵触 | 中 | 试点先行 + 培训 + 收集反馈迭代 |
| 冻结期业务中断 | 中 | 提前通知 + 临时表补录 + 缩短冻结期 |
| 引擎开发延期 | 中 | 批次1按优先级排序，先迁移简单客户 |
| 系统性能问题 | 低 | 试点期压测 + 索引优化 + 分页查询 |

## 6. 回滚机制

**触发条件**：
- 导入验证失败（行数/金额不一致）
- 系统上线后发现严重 bug
- 财务强烈抵触，无法使用

**回滚步骤**：
1. 停止系统使用
2. 恢复 Excel 台账（解封）
3. 补录冻结期数据到 Excel
4. 分析问题，修复后重新迁移

**数据保留**：
- 系统数据保留 30 天（只读）
- 30 天后删除，避免数据不一致
