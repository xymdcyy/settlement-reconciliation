# 业务模型

> 本文档描述结算对账中心的业务本质、角色、流程和核心概念。
> 所有技术设计都必须追溯到本文档的业务场景。

## 1. 业务本质

TCL 向 ~200 个渠道客户供应产品。每月需要完成：

1. **台账维护**：将新方舟系统导出的签收记录追加到各客户的层累台账
2. **对账核对**：对有对账单的客户（50-80 个），逐条核对我方签收与客户入库/结算记录
3. **开票管理**：对核对一致（或无对账单客户）的记录开具发票，回录发票信息
4. **差异处理**：识别并处理不一致记录（时间差挂账 vs 真差异调账）
5. **退货红冲**：退货时查找原蓝字发票，发起红字通知单流程

**核心资产**：每客户一份"签收-开票台账"（当前为 Excel，分散在财务各人电脑中）。

## 2. 角色与职责

| 角色 | 职责 | 当前痛点 |
|------|------|----------|
| **财务专员** | 负责若干客户的全部对账工作（台账/核对/开票/红冲） | Excel 分散、状态靠人记、跨月挂账靠人盯 |
| **财务主管**（你） | 制定标准、审批扩展列、配置引擎、监控全局 | 无法看到 200 客户的全局状态 |
| **税务** | 接收确认单，发起红字通知单 | 依赖财务手工查找蓝票 |
| **客户** | 提供对账单（部分客户）、确认红冲 | 格式千差万别 |

**关键关系**：每个客户有一个财务专员负责；一个财务专员负责多个客户。

## 3. 客户分层

| 层级 | 数量 | 特征 | 系统支持 |
|------|------|------|----------|
| **有对账单客户** | 50-80 | 客户每月提供入库/结算明细，需逐条核对 | 台账 + 核对 + 开票 |
| **无对账单客户** | 120-150 | 客户不提供记录，直接按我方台账开票 | 台账 + 开票 |
| **试点客户** | 4 | 潍坊百货、全福元、河北劲草、天猫优品 | 验证全部功能 |

## 4. 核心业务流程

### 4.1 月度对账循环（每个客户）

```
月初：
  1. 新方舟导出签收明细 → 追加到台账（层累）
  2. [有对账单客户] 接收客户对账单 → 上传解析

月中：
  3. [有对账单客户] 自动匹配 + 人工核对
     - 一致项 → 标记"可开票"
     - 不一致项 → 人工判断：
       * 时间差 → 挂入"未决差异池"，等下月
       * 真差异 → 新方舟调账（产生新记录，下月重新参与）
  4. 开票 → 回录发票号/开票日期
  5. [退货场景] 红冲流程（见 4.2）

月末：
  6. 统计本月对账情况（匹配率/未开票数/未决差异数）
  7. 未决差异池滚动到下月
```

### 4.2 退货红冲流程

```
1. 客户退货 → 新方舟产生退货记录（签收数量为负）
2. 财务在台账中查找原蓝字发票：
   - 匹配条件：同型号 + 单价容差≤0.01 + 签收数量>0
   - 取开票日期最新的一张
3. 生成确认单（含蓝票号、开票日期）→ 发给税务
4. 税务发起红字通知单 → 客户确认
5. 开具红字发票 → 回录红通号
```

### 4.3 拆分开票流程

```
场景：一行签收记录 5 台，但只需开 3 台发票
操作：
  1. 在台账中拆分该行：父行标记"已拆分"，生成两个子行（3台+2台）
  2. 子行继承父行全部字段，仅数量/金额不同
  3. 对 3 台子行开票，2 台子行保留未开状态
约束：子行可再拆分，但不可跨父行合并
```

## 5. 核心概念

### 5.1 台账行（Receipt）

台账的最小单位，包含：
- **系统字段**（94列，从新方舟导出）：单号、型号、数量、金额、日期、客户等
- **开票状态字段**（核心集）：是否开票、发票号、开票日期、拆分信息、备注
- **扩展字段**（可选，客户级配置）：红通号、红票勾选台数等
- **差异判断字段**：差异类型、差异说明、解决月份

**唯一性**：同一"新方舟销售单号"可有多行（拆分场景）。

### 5.2 未决差异池（Pending Discrepancy Pool）

跨月滚动的差异集合：
- **进入**：本月核对不一致，判断为时间差
- **消解**：下月客户对账单中出现，确认匹配
- **转真差异**：挂账超过 N 个月（通常 3 个月），人工确认需调账

### 5.3 对账单（Customer Statement）

客户提供的入库/结算记录，格式千差万别：
- 天猫优品：标准 Excel，PON 号匹配
- 全福元：余额调节表（流水+余额滚动）
- 重百：台账 Excel，订单备注提取凭证号
- ...

**解析方式**：每客户一个"引擎"（插件化，已有架构）。

### 5.4 发票（Invoice）

开票后产生：
- 蓝字发票：正常开票
- 红字发票：退货冲销，需关联原蓝票

**回录**：发票号、开票日期、（红冲场景）红通号。

## 6. 业务规则

### 6.1 匹配规则（有对账单客户）

**一致标准**：型号 + 数量 + 单价（容差 ≤0.01）完全匹配

**匹配键**：
- 优先：客户对账单中的我方单号（PON号/S101号）
- 降级：型号+数量+金额组合匹配
- 兜底：人工核对

### 6.2 开票规则

- 只有"核对一致"或"无对账单客户"的记录才能开票
- 开票后必须回录发票号和开票日期
- 支持拆分开票（一行拆多行，分别开票）

### 6.3 差异处理规则

| 差异类型 | 判断依据 | 处理方式 |
|----------|----------|----------|
| 时间差 | 本月客户未记录，但我方已签收 | 挂入未决池，等下月 |
| 客户未收货 | 我方显示已签收，客户否认 | 新方舟调账（红冲） |
| 我方未签收 | 客户已入库，我方无记录 | 补录签收 |
| 价格差异 | 型号数量对，价格差>0.01 | 调价（开退单+进单） |
| 退货差异 | 我方已退，客户未退 / 反之 | 调账或补退单 |

### 6.4 扩展列审批规则

- 核心集字段（5个）：所有客户强制启用
- 扩展字段：客户申请 → 主管审批 → 配置生效
- **禁止**：财务私自添加 Excel 列（系统外）

## 7. 当前痛点（系统要解决的问题）

1. **数据孤岛**：200 个 Excel 分散在各人电脑，无法汇总、交接、审计
2. **状态混乱**：`是否开票`列是记事本（`111`、`重复开具：xxx`），历史追溯靠猜
3. **未决池失控**：跨月挂账越积越多，无人知道哪些该催
4. **重复劳动**：红通查找、拆分、核对——同一逻辑每客户一份脚本/手工
5. **协作困难**：多人同时改一个 Excel，版本冲突

## 8. 成功标准

### 8.1 试点成功标准（3-5 客户，1-2 个月）

- [ ] 历史台账全量导入，数据核对无误
- [ ] 财务在系统里完成开票、拆分、红冲，不再打开 Excel
- [ ] 未决差异池可视化，能回答"哪些挂了超过 3 个月"
- [ ] 天猫优品的自动匹配率不低于现有脚本

### 8.2 全量推广成功标准（200 客户，6-12 个月）

- [ ] 所有客户台账集中管理，Excel 封存
- [ ] 有对账单客户的自动匹配率 ≥95%
- [ ] 未决差异池自动消解率 ≥80%（下月自动匹配）
- [ ] 财务工作效率提升 50%（从月对账 X 天降到 X/2 天）
